## Goal and prerequisites

Use .NET SDK `10.0.401` (see `global.json`), Python 3, Git and a disposable local workspace. Run the source commands in this tutorial from the repository root, unless a step says otherwise. Shell examples use macOS/Linux or Git Bash.

```sh
git clone https://github.com/mbo2olivier/enterprise-workflow.git
cd enterprise-workflow
dotnet --version
dotnet restore EnterpriseWorkflow.slnx --locked-mode
dotnet build samples/OrganizationWorkflow/Kernel/Example.Workflow.Kernel.csproj -c Release --no-restore
dotnet build samples/OrganizationWorkflow/Cli/Example.Workflow.Cli.csproj -c Release --no-restore
dotnet build samples/OrganizationWorkflow/Module/Example.Workflow.Module.csproj -c Release --no-restore
```

**Expected:** each build exits with code 0. A package-feed or SDK error must be resolved before moving on. These source projects use `ProjectReference`; do not substitute an older public package with the same version number.

## Create these project boundaries

```text
samples/OrganizationWorkflow/
├── Contracts/       IApprovalPolicy: shared business contract
├── Sdk/             ExampleWorkflowModule: runtime compatibility
├── Hosting/         shared service registrations and HTTP implementation
├── Kernel/          deployed executable and brand resources
├── Cli/             developer executable, few-example
├── Templates/       packaged module skeleton, config and localization
├── Module/          compiles the exact template source
├── PolicyApi/       local external-service demonstration
└── distribution.json
```

In your own repository, add `Security/` for the providers in chapters 5–6 and `Tests/` for their gateway contract tests. Keep business modules in separate projects or repositories as your teams grow. Do not put corporate authentication implementations in every module.
