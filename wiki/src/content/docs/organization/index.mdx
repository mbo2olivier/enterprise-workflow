Build a reusable platform for your organization: its own executable kernel, developer CLI, shared service contracts, module SDK and project templates. Then connect corporate identities and a second factor through compiled extensions.

<Aside type="note" title="Version and execution track">
This tutorial uses the repository source and locally built packages. The source distribution uses version `1.0.0-rc.1`; this does not imply that all additions are available in previously published packages. Build the local distribution as shown in chapter 3. The published-package [first workflow](../getting-started/first-workflow/) remains a separate track.
</Aside>

## What you will build

![The CLI and kernel share organization services and contracts; modules depend on the organization SDK.](/enterprise-workflow/diagrams/organization-platform.svg)

The fictional `Example.Workflow` platform has no bank dependency or secret. Its request process lets Alice submit a reason, Bob approve or decline, and a service call an HTTP policy API. The same packaged module can run in development and in the custom kernel.

## How to use the examples

Each source panel names its file. Panels are imported from source during the site build; missing files or excerpt markers fail the documentation build. Get the complete [organization sample sources](https://github.com/mbo2olivier/enterprise-workflow/tree/main/samples/OrganizationWorkflow) and the [security adapter library](https://github.com/mbo2olivier/enterprise-workflow/tree/main/wiki/examples/OrganizationSecurity). Their paths in the checkout are `samples/OrganizationWorkflow` and `wiki/examples/OrganizationSecurity`.

Chapters 1–4 and 8 use the existing executable sample. Chapters 5–6 provide compilable adapters and define the gateway your organization must implement against its identity and challenge services. They do not claim to provide a bank integration or a production OTP server.

For a bank, replace `Example` with your organization’s namespace and feed, then supply its identity, challenge and business-service gateways. Keep infrastructure credentials in host configuration; module developers consume contracts and the organization SDK.

Start with [the solution and contracts](solution/).
