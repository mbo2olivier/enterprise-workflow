# Preuve locale L9 — CLI, templates et runtime de développement

Date : 20 octobre 2026. Environnement local macOS arm64, SDK .NET `10.0.401`. **Implémentation locale livrée ; qualification CI Linux/macOS/Windows et scénarios complémentaires restants.** Aucun package n’a été publié sur NuGet.org. Les commandes et limites sont décrites dans le [guide CLI](../l9-cli.md).

## Livrables

- Outil .NET `ew` : `validate`, `inspect` (texte/JSON), `pack`, `verify`, `dev` ; `--module-directory` répétable pour les propriétaires d’artefacts exacts.
- Templates installables `ew-module` et `ew-embedded`, compilables hors du dépôt avec les packages locaux.
- Hôte local SQLite avec migrations explicites, UI L8 réutilisée, formulaires L8b, seed et sélecteur d’identité protégés par antiforgery, sessions réelles et bandeau de développement.
- Configuration JSON v1, SMTP explicite, surveillance par reconstruction/redémarrage, verrou d’espace local et réinitialisation volontaire par archivage.
- Validation du catalogue combiné, conservation des générations et refus d’un hash modifié sous une release existante ; préparation en sous-processus pour libérer les DLL.
- Stack Mailpit Docker Compose et procédures de qualification reproductibles, intégrées à la CI.

## Reproduction

```bash
dotnet restore EnterpriseWorkflow.slnx --locked-mode
dotnet build EnterpriseWorkflow.slnx --configuration Release --no-restore --disable-build-servers -p:UseSharedCompilation=false -m:1
dotnet test --project tests/EnterpriseWorkflow.Core.Tests/EnterpriseWorkflow.Core.Tests.csproj --configuration Release --no-build --no-restore
dotnet test --project tests/EnterpriseWorkflow.Extensions.Tests/EnterpriseWorkflow.Extensions.Tests.csproj --configuration Release --no-build --no-restore
dotnet test --project tests/EnterpriseWorkflow.Cli.Tests/EnterpriseWorkflow.Cli.Tests.csproj --configuration Release --no-build --no-restore
./scripts/qualify-l9.sh /tmp/ew-l9-qualification
pwsh tests/EnterpriseWorkflow.Web.Playwright.Tests/bin/Release/net10.0/playwright.ps1 install --with-deps chromium
./scripts/qualify-l9-browser.sh /tmp/ew-l9-qualification
```

Choisir un nouveau répertoire pour la qualification. Le premier script a réussi depuis un répertoire propre avec les packages locaux et la complétion d’une ancienne instance après redémarrage. Le test navigateur final utilise la CLI installée et une copie de LeaveRequest consommant ces packages ; ses quatre scénarios ont réussi, puis le runtime et Docker ont été arrêtés proprement. Le test Kernel distinct a également réussi. Les scripts conservent les artefacts et logs ; l’hôte et la stack SMTP du test navigateur sont arrêtés à la sortie. Le script de surveillance utilise une copie générée du module, modifie volontairement son code et conserve ses anciennes générations. Les tests locaux .NET nécessitent les canaux IPC hors sandbox ; aucun succès n’est déduit d’un test non exécuté.

## Corrections détectées pendant l’intégration

- Les contrats communs du loader doivent être matérialisés avant la création des contextes privés : des expressions `typeof` jetées pouvaient être optimisées et provoquer des identités CLR distinctes. Le chargement explicite des assemblies de contrats corrige le démarrage dans l’hôte autonome.
- Le nom de projet ne doit pas devenir directement un nom de classe C# : les noms contenant un point sont désormais acceptés par le template.
- La préparation cible l’assembly déclaré par MSBuild ; un module dépendant d’un autre module ne crée pas un second candidat d’entrée artificiel.
- Le packaging d’un module utilise son manifeste pour résoudre les fichiers ; il ne dépend pas du `.deps.json` d’une application. Sa génération est désactivée pendant cette publication temporaire pour éviter les erreurs de cache lors des publications répétées.
- L’URL doit être appliquée après la configuration de l’hôte ; le port annoncé correspond au port effectivement ouvert.
