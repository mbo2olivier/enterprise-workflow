# Preuve du lot L1

Date : 1er octobre 2026. Commit : changements de travail non encore commités au moment de la preuve.

## Périmètre livré

- solution `EnterpriseWorkflow.slnx` ciblant .NET 10 ;
- SDK épinglé sur `10.0.102`, C# 14, nullable et analyseurs .NET activés, avertissements traités comme erreurs ;
- projets `EnterpriseWorkflow.Abstractions`, `EnterpriseWorkflow.Core` et `EnterpriseWorkflow.Sdk` avec références unidirectionnelles ;
- versions NuGet centralisées et restaurations verrouillées ;
- tests xUnit v3 exécutés par Microsoft Testing Platform ;
- exemple `MinimalWorkflow` compilable et exécutable ;
- workflow GitHub Actions sur Ubuntu 24.04 x64, Windows 2025 x64 et macOS 15 ARM64.

## Commandes et résultats locaux

Environnement : macOS 26.3 ARM64, SDK .NET `10.0.102`, runtime .NET `10.0.2`.

```bash
dotnet restore EnterpriseWorkflow.slnx --locked-mode
dotnet build EnterpriseWorkflow.slnx --configuration Release --no-restore --disable-build-servers --maxcpucount:1
dotnet test --solution EnterpriseWorkflow.slnx --configuration Release --no-build --no-restore --max-parallel-test-modules 1
dotnet run --project samples/MinimalWorkflow/MinimalWorkflow.csproj --configuration Release --no-build --no-restore
```

Résultats : build réussi avec zéro avertissement et zéro erreur ; 2 tests réussis, 0 échec, 0 ignoré ; exemple exécuté et les trois assemblies chargées.

`--disable-build-servers --maxcpucount:1` a été utilisé localement après l’interruption d’un premier restore isolé du réseau. Le workflow CI conserve la commande standard sur ses runners propres.
