## Correction du package CLI absent — 20 novembre 2026

Cause confirmée par les propriétés MSBuild : le projet CLI utilise le SDK Web et ne déclarait pas `IsPackable=true`. Le feed de qualification contenait les quatre autres packages organisationnels, mais aucun `Example.Workflow.Cli` ; `dotnet pack` avait terminé sans produire ce package.

Correction : packaging explicitement activé ; le script vérifie l’existence des nupkg et l’identité/version de leur nuspec. Une phase `install` permet de reprendre un feed partiellement préparé sans reconstruire tous les packages ; les versions attendues viennent de `distribution.json`.

Validation ciblée : packaging Release du CLI réussi ; installation de `Example.Workflow.Cli` 1.0.0-rc.1 depuis un feed local isolé réussie ; l’outil installé affiche `Example.Workflow 1.0.0-rc.1` avec `distribution`. Trois tests Python rapides réussissent (absence du package, identité/version incorrectes, package conforme). La qualification complète n’a pas été relancée.

## Composition AddHttpClient en développement — 20 novembre 2026

Le garde-fou traitait toute inscription supplémentaire d’un type déjà présent comme un remplacement. Cela bloquait les configurateurs d’options additifs utilisés par AddHttpClient. Les ajouts IConfigureOptions/IPostConfigureOptions/IValidateOptions hors options framework et ASP.NET sont désormais admis ; supprimer une inscription existante ou ajouter un service de sécurité reste interdit, y compris par options génériques. Le diagnostic précise maintenant le type concerné.

Compilation ciblée réussie, zéro erreur/avertissement. Neuf tests CliBuilderTests réussis, dont ajout de client HTTP typé sur services web, refus de modification des options d’authentification et refus de remplacement d’un service existant. Aucun parcours natif dev ou campagne lourde lancé.
