# L13 — découverte des modules : preuve locale et qualification déléguée

Date : 24 novembre 2026. Statut : implémenté localement ; qualification lourde en attente du porteur. L14 (retrait/historique autonome) et L15 (Studio) ne sont pas implémentés. Aucun commit, push ou package public publié par cette tâche.

## Livré

- `WorkflowModuleDiscovery.FindArtifacts` : parcours déterministe borné, racine candidate acceptée, arrêt de descente au premier manifeste, liens/jonctions non suivis, erreurs d’accès non masquées.
- `WorkflowModuleCatalog.Discover` : validation des manifestes et hashes, refus des doublons avant exclusion, filtre de compatibilité runtime avant activation ; réutilisation du loader exact existant. `Load` explicite reste inchangé dans sa sémantique.
- `WorkflowModuleSource.Load` et SDK Hosting : `Modules:RootDirectory` configuré prend la priorité exclusive. La liste individuelle n’est ni fusionnée ni validée dans ce mode. Racine invalide : échec, aucun fallback ; sans clé de racine : mode explicite historique.
- Racines relatives de découverte résolues contre le content root ; chemins relatifs du fallback explicite conservant leur résolution historique. `ConfigureDiscovery` et `Modules:Discovery` permettent les limites de scan ; diagnostics stables et journalisation typée.
- Valeurs par défaut : profondeur 8, 10 000 répertoires, 1 024 candidats, 100 000 entrées parcourues. Le plafond supplémentaire d’entrées borne les dossiers riches en fichiers.
- Configuration Kernel, documentation, exemples et scripts de qualification adaptés. Le scénario Kernel L9 utilise une racine contenant l’artefact et une liste individuelle invalide ; le Kernel personnalisé de la recette L12 utilise sa racine d’artefacts.
- Aucune migration SQL, changement de format/hash ou modification du cycle dev. La rétention fondée sur les définitions publiées reste intégralement applicable jusqu’à L14.

## Choix techniques et arbitrages

Aucun arbitrage produit bloquant supplémentaire. Les limites ci-dessus sont des défauts configurables, décrits dans la spécification. Le scan n’active jamais arbitrairement une DLL sans manifeste. Les artefacts incompatibles intègres sont exclus avec motif ; les corruptions et doublons demeurent bloquants, y compris parmi les candidats incompatibles. Aucune sélection automatique de la seule dernière version.

Les artefacts et le répertoire doivent rester stables pendant la découverte/activation. Les contrôles de liens ne constituent pas une sandbox contre un acteur modifiant simultanément le système de fichiers ; les modules restent du code approuvé.

## Correctif de chargement des langues configurées

Le binder .NET ajoutait SupportedCultures configuré au tableau préinitialisé de WorkflowLocalizationOptions, produisant des doublons artificiels. WorkflowLocalizationOptions.FromConfiguration lit désormais le tableau séparément : les langues configurées remplacent les défauts, les vrais doublons et tableaux explicitement vides restent refusés. Hosting et DevHost utilisent le même lecteur ; l’interface et les notifications réutilisent les options validées.

Vérifications : compilation Release complète sans avertissement/erreur ; 15 tests ciblés Localization/Hosting/ModuleSource réussis, aucun ignoré ; helper Python de republication vérifié sur fichiers temporaires avec publication simulée, préservation exacte des configurations après succès et échec. Aucun serveur HTTP, navigateur ou campagne lourde lancé. La recette fournit `prepare-l13-config.py --refresh-hosts` pour actualiser les hôtes déjà publiés sans perdre leurs fichiers de configuration ; aucune migration de base requise.
